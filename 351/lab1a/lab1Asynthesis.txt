1) Steps:

Consider pointers `ptr1` and `ptr2` that point to the two addresses, where
`ptr2` comes after `ptr1`.

Initially, one might attempt to do `ptr2 - ptr1` to calculate the difference
between the pointers in bytes (this is what I tried as well).

However, pointer arithmetic in C is *scaled* by the size of the underlying data
type. Since we are trying to find this scale factor, we cannot use this approach
- it's a Catch-22.

Therefore, one might choose to first cast the pointers to another data type. But
what do we cast to? I tried casting to an `int`, but found a compiler warning:

```
-Wpointer-to-int-cast: Cast to smaller integer type 'int' from 'int *'
```

We learned from lecture that pointers are 8 bytes, but `int`s are only 4 bytes.
Therefore, we cast to a `long`, which is 8 bytes on a 64-bit Unix system. This
causes the compiler warning to go away.

Lastly, since we were asked to calculate the difference, we simply subtract
the casted `ptr1` from `ptr2`.

Here is the code snippet (from the `int_size` example):

```c
(long)int_ptr2 - (long)int_ptr1
```

2) Explain:

`swap_ints` must take two pointers because we need to modify data outside the
scope of the function. Pointers allow us to directly modify data by editing the
content at specific addresses of memory *outside* the scope of the function.

We would be able to *locally* swap `int`s if they weren't passed as pointers.
However, without knowing the external addresses, the changes we make wouldn't
affect the variables outside of the function, essentially making the function
useless.
