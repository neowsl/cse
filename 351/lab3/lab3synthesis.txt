2) Minimum len to cause a segfault: 
   Step-by-step calculation:

To cause a segfault, we simply need to corrupt at least one
byte of the return address. Since the return address is
stored on the stack, we should be wary of any instructions
that modify `%rsp` (the stack pointer) inside of
`part_2()`. There is one instruction:

`<part_2+0>: sub $0x48, %rsp`

Next, we need to know where `array` starts so we have a
baseline of where to begin our buffer overflow. Since
`array` is the first argument to `fill_array()`, we should
expect the starting address to be moved into `%rdi`.
Indeed, we find the following instructions:

`<part_2+14>: lea 0x10(%rsp), %rax`
`<part_2+24>: mov %rax, %rdi`

The `lea` instruction suggests that `array` starts
0x10 = 16 bytes above the stack pointer. Since we initially
subtracted 0x48 = 72 bytes from the stack pointer, adding
back 16 gives us 56 bytes of data above `array` that we
must overwrite to reach the return address.

Since we must corrupt the return address, we need to write
at least 57 bytes into `array`. `array` is an array of
4-byte ints, so we take `ceil(57 / 4) = 15` to find that we
need a minimum of `len = 15` to corrupt the return address
and cause a segfault.

And indeed, setting `len = 14` doesn't segfault, and
`len = 15` does!
